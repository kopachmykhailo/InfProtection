## Біграмні шифри

Квадрат має алфавіт `ABCDEFGHIKLMNOPQRSTUVWXYZ`: J перед обробкою переходить в
I. Ключ нормалізується до NFC та верхнього регістру; повтори прибираються зі
збереженням першої появи, а решта алфавіту дописується в кінець квадрата.

Текст також нормалізується через NFC і переводиться у верхній регістр. Типово
пробіли, розділові знаки й сторонні символи відкидаються. Параметр `--strict`
натомість відхиляє їх. Однакові сусідні літери розділяються заповнювачем X, а
для літери X використовується Q; непарний фінал доповнюється так само.
Розшифрування повертає підготовлений потік — заповнювачі автоматично не
видаляються, бо їх неможливо однозначно відрізнити від вихідних літер.

```powershell
python lab3.py square --key MONARCHY
python lab3.py prepare --text BALLOON
python lab3.py encrypt --algorithm playfair --key MONARCHY --text INSTRUMENTS
python lab3.py decrypt --algorithm playfair --key MONARCHY --text GATLMZCLRQXA
```

`prepare` показує біграми з пробілами. Шифротекст приймає як без пробілів, так і
з пробілами між біграмами.

### Двоквадратний шифр

Перша відкрита літера береться з лівого квадрата, друга — з правого. Для різних
рядків формується пара з правого квадрата `(r1, c2)` та лівого `(r2, c1)`; для
однакових рядків — із правого `(r1, c1)` та лівого `(r2, c2)`. Розшифрування
виконує обернене відображення за тими самими двома незалежними квадратами.

```powershell
python lab3.py square --key EXAMPLE --right-key KEYWORD
python lab3.py encrypt --algorithm double --key EXAMPLE --right-key KEYWORD --text SECURITY
python lab3.py decrypt --algorithm double --key EXAMPLE --right-key KEYWORD --text NMDWQIPP
```

## Vernam XOR

Повідомлення кодується у UTF-8 без автоматичної нормалізації. Ключ створюється
через `secrets.token_bytes` (системний CSPRNG) і має рівно стільки байтів,
скільки UTF-8-повідомлення. Шифротекст і ключ відображаються в Base64.
Base64 перевіряється строго, довжини байтів мають збігатися, а розшифрований
текст проходить суворе UTF-8-декодування.

У репозиторії вже є демонстраційний [`input.txt`](input.txt). Його потрібно
читати; файли результатів (`ciphertext.b64`, `key.b64`, `recovered.txt`)
створюються командами автоматично в поточній папці. Перед запуском відкрийте
PowerShell у папці проєкту:

```powershell
python lab3.py encrypt --algorithm vernam --input input.txt --output ciphertext.b64 --key-output key.b64
python lab3.py encrypt --algorithm vernam --text "Текст" --output ciphertext.b64 --key-output key.b64
python lab3.py decrypt --algorithm vernam --input ciphertext.b64 --key-file key.b64 --output recovered.txt
Get-Content -Encoding utf8 recovered.txt
```

Шифротекст і ключ — різні UTF-8-файли з Base64-рядками; ці файли не потрібно
створювати заздалегідь. Ключ треба зберігати окремо, захищати й ніколи не
використовувати повторно. `--key-output` створює чутливий файл: використовуйте
лише вигадані тестові дані та належне захищене середовище. Порожнє повідомлення
дає порожні шифротекст і ключ; такий режим не призначений для розподілу ключів.

## Контрольні вектори

| Алгоритм | Вхідні дані | Очікуваний результат |
|---|---|---|
| Playfair, ключ `MONARCHY` | `INSTRUMENTS` | `GATLMZCLRQXA` |
| Playfair, розшифрування | `GATLMZCLRQXA` | `INSTRUMENTSX` |
| Два квадрати `EXAMPLE` / `KEYWORD` | `SECURITY` | `NMDWQIPP` |
| Vernam, `HELLO`, ключ HEX `1A2B3C4D5E` | шифротекст | `Um5wARE=`; ключ Base64 `Gis8TV4=` |
| Vernam, `Я`, ключ HEX `0102` | шифротекст | `0a0=`; ключ Base64 `AQI=` |

Фіксовані Vernam-ключі в таблиці — публічні навчальні вектори тільки для
автоматизованих тестів. Вони не використовуються CLI для звичайного шифрування.

## Структура та обмеження

- `lab3_cipher.py` — побудова/форматування квадратів, підготовка біграм,
  шифрування, розшифрування, перевірка Base64 та XOR.
- `lab3.py` — CLI, UTF-8-файли та атомарний запис кожного результатного файлу.
- `tests/test_lab3.py` — вектори, зворотність, вхідна валідація, Unicode,
  файловий CLI, генерація ключів та демонстрація наслідку повторного ключа.

Одноразовий блокнот має абсолютну секретність лише за умов незалежного
рівномірного CSPRNG-ключа, довжини не меншої за повідомлення, таємності та
одноразового використання. XOR не забезпечує цілісності чи автентичності:
зміна біта шифротексту передбачувано змінює відповідний біт відкритого тексту.
Повторне використання ключа відкриває XOR двох відкритих повідомлень.
